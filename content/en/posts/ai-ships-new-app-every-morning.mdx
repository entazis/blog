Every morning something new appears on my domain.

A new subdomain.
A new tiny tool.
Something I didn't build.

Sometimes it's a regex tester.
Sometimes a JWT decoder.
Sometimes something slightly weird.

I open it, try it, and only then realize what my AI assistant decided to ship overnight.

---

A few weeks ago, I set up a small experiment.

I gave my personal AI assistant a new skill: **deploy applications**.

Every morning at **06:00, a cron job triggers it**.

Its task is simple:

- look at my recent work
- scan current developer trends
- generate a small useful tool
- deploy it to my domain

So every day it ships **a brand new app**.

Usually it's a surprise.

## The rules

The assistant has strict constraints:

- Vanilla HTML / CSS / JavaScript
- No frameworks
- No dependencies
- Fully static
- Client-side only

The result is a growing collection of **tiny developer utilities**.

No backend.
No database.
No build step.

Just a few hundred lines of generated HTML, CSS and JavaScript.

## Why no frameworks?

Because for tools like these, they simply aren't necessary.

When AI can generate UI instantly, writing raw HTML and JavaScript becomes almost free.

The overhead of frameworks starts to feel disproportionate.

If something needs to change, the AI can simply generate the app again.

## What if AI responded with apps instead of text?

While running this experiment another idea started forming.

Today we mostly interact with AI through **text**.

We describe something.
The AI answers with more text.

But text is not always the best interface.

If generating small apps becomes trivial, an AI could respond with **interactive interfaces instead**.

Instead of paragraphs it might send:

- a dropdown with options
- a canvas to sketch something
- a visualization
- a small form
- a mini tool to explore a problem

The response is no longer just text.

It becomes **an interface you interact with**.

The interaction becomes something like:

**prompt → generated app → interaction → result**

Instead of describing things in messages, we start **interacting through software**.

## My favorite part

Every morning I open my domain and see what the AI built overnight.

Sometimes useful.
Sometimes weird.
Always interesting.

A while ago I wrote that working with AI sometimes feels like [managing a team of developers](/en/notes/coding-feels-managerial-now).

---

Something interesting happens when software becomes this cheap to create.

It stops being something we carefully plan and slowly build.

It becomes something we **generate whenever we need it**.

---

If that future arrives, the question might change from:

**"What software should we build?"**

to

**"What software should exist right now?"**
